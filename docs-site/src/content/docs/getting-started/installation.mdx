This page is for whoever runs the server. If someone else hosts it for you, skip ahead to
[Connect to a budget](../connecting/). Installation means a Docker container - that is the only
supported route. Compose is the shortest one.

:::note[You still need Actual Budget]
Bench connects to an [Actual Budget](https://github.com/actualbudget/actual) server. It does not ship
one. Get your Actual Server running first - plus
[actual-http-api](https://github.com/jhonderson/actual-http-api) if you plan to use HTTP API Server
mode.
:::

## Before you start

- **Docker** (and optionally Docker Compose) installed on the host.
- A spare **port** on the host. The container listens on **3000**.
- Somewhere to put a **persistent volume** for the metadata database, or Bench forgets itself every
  restart.
- **Browser access** to wherever you publish it.
- For **Direct Actual Server mode**: your *browser* has to reach the Actual Server, which brings CORS
  and cross-origin isolation requirements with it. See [Connect to a budget](../connecting/).
- For **HTTP API Server mode**: the *container* has to reach `actual-http-api`.

## Choose a release channel

Actual Bench publishes multi-architecture images (`linux/amd64` and `linux/arm64`):

| Tag | Stability | Use it when |
|---|---|---|
| `latest` | Stable | Normal production / self-hosting (default) |
| `:<version>` (e.g. `:1.2.4`) | Stable, pinned | You want a specific, unchanging version |
| `edge` | Unstable - rebuilt on every merge | Testing the newest changes before a release |

:::caution
`edge` tracks the `main` branch and can change at any time. Do not use it as your normal production
image - prefer `latest` or a pinned `:<version>`.
:::

## Install with Docker Compose

Create a `docker-compose.yml`:

```yaml
services:
  actual-bench:
    image: xrous/actual-bench:latest
    container_name: actual-bench
    ports:
      - "3000:3000"
    environment:
      ACTUAL_BENCH_DB_PATH: /data/actual-bench.sqlite
      # --- Optional settings (uncomment to use; see the Configuration guide) ---
      # DIRECT_BROWSER_API: "0"                    # offer only HTTP API Server mode
      # LOG_LEVEL: info                            # debug | info | warn | error
      # SYNC_VAULT_KEY: "<strong-secret>"          # enable unattended server-side sync
      # SYNC_SCHEDULER_SECRET: "<strong-secret>"   # enable the external scheduler trigger
    volumes:
      - actual-bench-data:/data
    restart: unless-stopped

volumes:
  actual-bench-data:
```

Start it:

```bash
docker compose up -d
```

A basic setup needs no environment variables at all. `ACTUAL_BENCH_DB_PATH` appears above only to make
the metadata location obvious - it already defaults to that path. Everything commented out is
optional; [Configuration](../../administration/configuration/) says what each one does.

## Install with the Docker CLI

The equivalent without Compose:

```bash
docker run -d \
  --name actual-bench \
  --restart unless-stopped \
  -p 3000:3000 \
  -v actual-bench-data:/data \
  xrous/actual-bench:latest
```

## Open Actual Bench

Open the app in your browser:

- Local host: `http://localhost:3000`
- Remote host: `http://<your-server>:3000`, or your reverse-proxy URL

You should land on the connection screen. [Connect to a budget](../connecting/) takes it from there.

:::tip[Use HTTPS when it isn't just localhost]
The moment Bench is reachable from anywhere but your own machine, put HTTPS in front of it - a reverse
proxy is fine. Direct Actual Server mode needs a secure, cross-origin-isolated context and will not
work without one. See [Deployment](../../administration/deployment/).
:::

## Verify the installation

1. The app loads and shows the connection screen.
2. The version appears in the sidebar footer (for example `v1.2.4`).
3. Open **App Health** (under **Tools**) and confirm:
   - **Writable** is `Yes`.
   - **Schema** shows a version number (not `Not initialized`).
   - **Persistence** reads *Persistent when /data is mounted*.

**Writable** saying `No`, or persistence looking wrong, means the mount holding the database - or its
permissions - is wrong. Fix that before you connect anything.

## Persistent metadata storage

Bench keeps its own workflow metadata in a SQLite database at `/data/actual-bench.sqlite`; set
`ACTUAL_BENCH_DB_PATH` to move it. Persist and back up the volume that database sits on - `/data`
unless you moved it, in which case persist the directory `ACTUAL_BENCH_DB_PATH` names instead.
Recreate the container without it and that metadata is gone.

:::note[What `/data` is - and isn't]
This database is not a copy of your budget. It holds Bench's own workflow data - and, only if you turn
those features on, encrypted remembered-server or unattended-sync credentials.
:::

## Update the container

To move to a newer image:

```bash
docker compose pull
docker compose up -d
```

Before a real upgrade, read [Upgrading and Backups](../../administration/upgrading-and-backups/). It
covers backups, pinning a version, and what happens to the database.
