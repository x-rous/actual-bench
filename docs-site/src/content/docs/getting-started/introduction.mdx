Some jobs are miserable one row at a time. Others are easy to do and hard to check. Actual Bench is
for those. Your normal budgeting stays where it is.

## Is it for you?

Probably, if any of this sounds familiar:

- You have enough accounts, payees, categories, schedules, tags or rules that maintaining them one at
  a time has stopped being reasonable.
- You plan several months at once, or draft the numbers in a spreadsheet first.
- Your rules have piled up and you no longer know which ones overlap, duplicate each other, or point
  at something that no longer exists.
- You reconcile from downloaded statements and want the comparison to survive closing the tab.
- You keep more than one budget file - per person, per business, per currency.
- You want to ask your data a question no screen answers.

If you mostly enter transactions, check balances and nudge this month's budget, stay in Actual Budget.
This is a workbench. You visit it for the big jobs.

## What it does not replace

It does not replace:

- Everyday transaction entry and mobile budgeting in Actual.
- Actual's normal budget views and reports.
- Actual's bank connections. Actual owns the link to your bank. Bench decides when the sync runs and
  reports what came back, but never touches the connection itself.
- Actual's day-to-day reconciliation. Bench adds a separate workbench for the times you want to
  import a whole statement and audit it line by line.
- The official Actual Budget documentation.

## Why the workflows feel different

Because the safe way to do a job depends on the job. Maintenance work stages until you press **Save**.
Sync and statement reconciliation preview first, then apply what you picked. Diagnostics never write at
all. Notes and carryover toggles save the instant you touch them - deliberately, and the pages say so.
[Work safely](../core-concepts/) covers all four in a few minutes.

## What you need

- An Actual Server you already run, and a current browser.
- Actual Bench itself - or the [live demo](https://actual-bench-demo.vercel.app), if you are still deciding.
- For **Direct** mode: a browser that can reach the Actual Server URL, over HTTPS, with CORS allowed
  or the server proxied same-origin.
- For **HTTP API Server** mode: a running `actual-http-api`, its URL, and its `ACTUAL_API_KEY`.
