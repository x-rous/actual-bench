# Actual Bench — Demo Backend

Runs `actualbudget/actual-server` (sync) + `jhonderson/actual-http-api` (REST) in
a single container. The two demo budgets are **baked into the image** and
`start.sh` re-copies them on every boot, so the demo always resets to a clean
state.

This folder is the source for the Hugging Face Space
<https://huggingface.co/spaces/x-rous/actual-bench-demo>.

## Files

| File | Purpose |
|---|---|
| `Dockerfile` | Builds the combined sync + REST image (exposed on port 7860). |
| `start.sh` | Boots the sync server, waits, then starts the REST wrapper. |
| `seed-data/` | Pre-synced Envelope and Tracking budgets (generated by `generate-seed.mjs`). |
| `generate-seed.mjs` | Headless script that creates and validates both budgets from equivalent sample data. |
| `seed-scenario.cjs` | Deterministic household categories, seasonal plans, month scenarios, tags, and demo names. |

## Regenerating the seed budget

From the repo root:

```bash
npm install --no-save @actual-app/api@26.8.1 @actual-app/sync-server@26.8.1
node demo/generate-seed.mjs
```

It spins up a temporary local sync server and creates these files with equivalent
accounts, categories, rules, schedules, and transactions:

- `Live Demo - Envelope` — Envelope mode;
- `Live Demo - Tracking` — Tracking mode, including planned income.

Each file contains twelve completed months plus the current partial month of a
coherent household story: 50 household categories, seasonal budget plans, good
and difficult months, more than 500 transactions, realistic transfers and split
purchases, 10 described tags with tagged activity, 12 schedules, and 30+ rules.
The intentional rule-diagnostic examples cover duplicate, near-duplicate,
shadowed, broad-match, and contradictory patterns without corrupting the file.

Generation fails unless both files meet the expected data thresholds, retain
their requested modes, and have identical transactions and expense plans.
The final server records are remapped to the demo's stable Sync IDs so routine
seed refreshes do not require changing the Demo UI environment variables.

The script writes both synced files to `demo/seed-data/` and prints the Sync IDs
to use as `DEMO_BUDGET_SYNC_ID` and `DEMO_TRACKING_BUDGET_SYNC_ID` in Vercel.
The server password is printed too — set it as the `ACTUAL_SERVER_PASSWORD`
secret on the Space.

## Deploying to the Space

```bash
git clone https://huggingface.co/spaces/x-rous/actual-bench-demo
# copy README.md, Dockerfile, start.sh, seed-data/ into the clone
cd actual-bench-demo && git add . && git commit -m "demo backend" && git push
```

Then set Space secrets: `API_KEY` (any string → `DEMO_API_KEY` in Vercel) and
`ACTUAL_SERVER_PASSWORD` (the one printed by the seed script). Configure both
printed budget Sync IDs on Vercel; the one-click demo stays disabled if either
is absent.

See `docs/DEMO_DEPLOYMENT.md` for the full end-to-end guide.
